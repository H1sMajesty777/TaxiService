**Дисциплина:** «Программирование корпоративных систем». **Вариант 34:** «Служба такси». **Группа:** ЭФБО-09-24.

## Цель и результат

Сделать Android-клиент к Spring Boot из КР № 3. Заказы, тарифы, заметки, аналитика, пользователи и аудит доступны через один REST API. Роль определяется сервером. Интерфейс учитывает роль при показе функций записи и администрирования.

## Сборка и запуск

1. Из корня репозитория поднимите `docker compose up -d --build --wait`. Убедитесь, что [health](http://127.0.0.1:8081/actuator/health) возвращает `UP`.
2. Откройте папку `kr-04` в Android Studio, выполните Gradle Sync. Нужны JDK 17 или 21 для Gradle, Android SDK 35 и Android Build Tools 35.0.0. Исходный и целевой уровни Java — 17.
3. Запустите эмулятор Android API 35 и конфигурацию `app`. На этом компьютере создан AVD `MireaTaxiApi35`. Для эмулятора адрес по умолчанию — `http://10.0.2.2:8081/`.
4. На экране входа укажите учётную запись из КР № 3. Если пароль временный, установите постоянный. В главном меню появятся разделы, соответствующие вашей роли.

Из папки `kr-04`:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

Готовый диагностический APK лежит в `app/build/outputs/apk/debug/app-debug.apk`. Для установки из терминала используйте `adb install -r app/build/outputs/apk/debug/app-debug.apk`, когда нужное устройство доступно в `adb devices`.

Для другого локального порта укажите, например, `-PtaxiDebugUrl=http://10.0.2.2:18083/` при сборке. Для физического устройства через USB можно воспользоваться `adb reverse tcp:8081 tcp:8081` и собрать debug с `-PtaxiDebugUrl=http://127.0.0.1:8081/`. Release принимает HTTPS-адрес из `-PtaxiReleaseUrl`. Адрес-заглушку нужно заменить для выпуска. Разрешение открытого HTTP включено только в debug-манифесте.

### Поток запроса

При открытии заказов клиент собирает параметры страницы и фильтра в `Map`. `TaxiApi.rides` адресует их как query-параметры, Gson читает ответ `Page<Ride>`. Ответ применяется в главном потоке, `RecyclerView` рисует текущие карточки. При смене страницы или фильтра выполняется новый запрос. При жесте обновления клиент перезагружает текущую страницу. Отдельный счётчик запросов блокирует запоздалый ответ на уже сменившуюся страницу.

Для редактирования приложение получает пассажиров и тарифы, открывает форму, проверяет локальный формат и отправляет `PUT` с текущим `version`. Бизнес-правила дополнительно проверяет сервер. При конфликте сервер возвращает 409, приложение показывает сообщение и предлагает обновить карточку перед повтором.

### Токены и восстановление

В `POST /api/auth/login` передаётся `clientType: NATIVE`. Access JWT записывается в поле `accessToken` в памяти процесса. Случайный refresh-токен шифруется AES/GCM. Ключ создаётся в Android Keystore, а случайный IV и зашифрованные байты сохраняются в `taxi_session`. Пароль используется при запросе входа или смены и не сохраняется в настройках.

Interceptor передаёт `Authorization: Bearer ...` и `X-Correlation-ID`. При 401 Authenticator выполняет refresh синхронизированно. Если другой запрос уже обновил access-токен, используется эта новая пара. После refresh исходный запрос повторяется один раз. Для обновления используется отдельный Retrofit-клиент без Authenticator, поэтому цепочка не вызывает себя. При остановке приложения access JWT исчезает. Следующий запуск читает зашифрованный refresh, обновляет сессию и возвращает пользователя в меню. При выходе сервер получает запрос отзыва и локальная сессия очищается.

### CSV

Для входного файла используется Android Storage Access Framework. Приложение читает байты через `ContentResolver`, отправляет файл `multipart/form-data` на preview и показывает число корректных и ошибочных строк. При успешной проверке оператор подтверждает применение. Скачивание использует выбранный пользователем документ и передаёт текущие фильтры списка в серверный экспорт.

## Проверка

`testDebugUnitTest` проверяет сложность пароля, стоимость с десятичной запятой, преобразование статуса и разбор даты. `assembleDebug` собирает APK. В эмуляторе API 35 проверены установка, вход под администратором, заказы и карточка, запись и чтение заметки, аналитика, хранение зашифрованного refresh, восстановление после остановки процесса и выход. Для этой проверки использовался отдельный сервер на порту 18083. APK для демонстрации собирается с основным портом 8081.

Файлы в репозитории используют UTF-8. На Windows Gradle запускается с системной кодировкой для совместимости файлов аргументов Java с кириллицей в путях, а для компиляции исходников отдельно задана UTF-8.
