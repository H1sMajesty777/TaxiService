# Отчёт по КР № 2. Настольное приложение

**Дисциплина:** «Программирование корпоративных систем». **Вариант 34:** «Служба такси». **Группа:** ЭФБО-09-24.

[Условие КР № 2 в Moodle](https://online-edu.mirea.ru/mod/assign/view.php?id=933004) · [Сквозная архитектура](../docs/ARCHITECTURE.md)

## Цель и результат

Перенести работу диспетчера из консоли в настольное приложение JavaFX, сохранив PostgreSQL и правила работы с заказом. Рабочее окно содержит таблицу заказов, справочник пассажиров, поиск, фильтры, сортировку, действия над заказом, статистику и экспорт Excel.

## Инструменты и запуск

Из корня репозитория в PowerShell:

```powershell
docker compose up -d --wait postgres
.\scripts\Use-TaxiEnvironment.ps1
mvn -q -pl kr-01 install
mvn -q -f kr-02/pom.xml javafx:run
```

Требуются JDK 21 и Maven 3.9+. Maven сначала устанавливает JAR КР 1 в локальный репозиторий. КР 2 использует его как зависимость `taxi-console`, поэтому изменения общих сервисов достаточно собрать командой `install`. Настройки JDBC передаются через `TAXI_DB_URL`, `TAXI_DB_USER` и `TAXI_DB_PASSWORD`. На учебной базе скрипт подставляет параметры корневого Compose. Пример запуска с отдельным PostgreSQL описан в [отчёте КР 1](../kr-01/README.md#свой-postgresql).

Готовый Student Hub из архива курса запускался на отдельных портах через Docker Compose. Проверка его веб-интерфейса вернула HTTP 200, health показал `UP`. В собственном JavaFX-клиенте соединение идёт через JDBC непосредственно в базу варианта.

## Что было сделано

1. Создан Maven-модуль и добавлены JavaFX Controls, FXML и зависимость на КР 1.
2. Подготовлены разметка `dispatch.fxml` и стиль `dispatch.css`. В FXML описаны элементы окна, колонки, вкладки и обработчики.
3. Связаны поля и действия контроллера. Для основной таблицы создана цепочка `ObservableList → FilteredList → SortedList → TableView`.
4. Добавлены формы создания и редактирования, выбор пассажира, смена статуса и подтверждение удаления. JavaFX проверяет формат ввода, сервис повторно проверяет предметные правила.
5. Подключены статистика и Excel-выгрузка через существующий `ReportService`.

## Как проходит действие

При открытии окна `FXMLLoader` связывает заранее созданный контроллер с элементами по `fx:id` и выполняет `initialize()`. Полученные из PostgreSQL модели отправляются в `orderRows`. `FilteredList` оставляет подходящие строки, а `SortedList` использует компаратор из заголовков `TableView`. Дата сравнивается как `LocalDateTime`, сумма — как `BigDecimal`. Изменение фильтра пересчитывает отображение без нового JDBC-запроса. Кнопка «Обновить» перечитывает базу.

Для создания оператор нажимает «Новый заказ». Контроллер запрашивает пассажиров и передаёт их в `RideForm`. Форма превращает выбранные значения в `RideRequest` и вызывает `RideOrderService.createRide`. Если проверка проходит, репозиторий вставляет заказ, PostgreSQL присваивает ID, диалог закрывается, таблица обновляется. При редактировании передаётся прочитанная версия. При удалении сервис получает ID и версию только после подтверждения.

Когда выбрана строка, приложение показывает имя и телефон связанного пассажира под таблицей. Во вкладке «Пассажиры» доступен полный список. Шаги смены статуса берутся из `RideStatus.canChangeTo`. Кнопки редактирования и удаления отражают текущее состояние заказа, а сервис защищает операцию при изменениях из другого клиента.
